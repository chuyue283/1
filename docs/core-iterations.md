## 迭代 1：双人格（小鱼 / 鲸娘）

**原始需求**（摘录）

> 「人格切换：语音和文字输入都能唤醒……唤醒词：小鱼，叫那个姐姐出来，或者：小鱼，把姐姐叫出来。……唤醒过程中让她做个动作……御姐人格唤醒成功之后先让她说一句话：叫我出来干嘛 / 又要干嘛（两句写成代码，随机挑一句让 7B 模型造句）……御姐人格的音色换成 Fish-ID 325afed0……换回第一人格的指令（只在第二人格状态生效）：让小鱼出来吧……记忆共享。」

**做法**

1. 在 `dsh-pet/lib/index.js` 里新增人格引擎：`persona.json` 存状态（who / 上次鲸娘时间 / 小鱼在场时长）。
2. `petPersonaTrigger(text)` 用正则拦截切换词，命中后走独立分支，不进入普通对话。
3. 两个人格用不同模型、不同音色、不同 system prompt；开场白由代码给模板、模型造句。
4. 记忆写入加 `who` 字段，检索时按人格过滤。

**遇到的 Bug**

| 现象 | 原因 | 修法 |
|---|---|---|
| 切鲸娘时先说了一句小鱼的声音 | `writePet("say")` 会自动发声，代码又额外调了一次 `speakPetLine` | 只保留一次发声，先把音色写进 pending |
| 出场动画不播 | 动画名写错（`原地小憩` vs `原地小憩沉眠`），且白名单没登记 | 改名 + 在 `animations.events` 登记 |
| 报 `no adapter registered for provider 'undefined'` | 模型参数传了字符串，路由要 `{provider, model}` | 改成对象 |
| 报 `provider 'ollama-local' has no configured model 'qwen2.5:7b-instruct'` | 供应商没登记 7B | 在 `cordis.patch.yml` 的 models 列表补一行 |

## 迭代 2：单向记忆（鲸娘可见小鱼，小鱼不可见鲸娘）

**原始需求**

> 「我设定的是小鱼看不到鲸娘的记忆但鲸娘能看见小鱼的记忆。……应该改成是一条单通道。」

**做法**

- 检索：小鱼只取 `who != jingniang`；鲸娘取全部，并对小鱼的记录加「（这是小鱼和你说的）」标注。
- 切换时：切到鲸娘**不清空**最近对话；切回小鱼才清空（用 `readMemory/writeMemory` 精确清空那一只宠物的 entry）。

**Bug**：最初把清空写成 `entry.messages.length = 0`，但那时 `entry` 还没定义，异常被 `try/catch` 吞掉 → 看起来"清空没生效"。
**修法**：先 `const mem = await readMemory()` 取到 entry 再清空、再写回。

## 迭代 3：语音守护进程重建（事故恢复）

**背景**：一次目录搬迁时，`dsh-pet\voice` 这个 junction 被展开，造成递归复制，`daemon.ps1` 丢失 → 她只出字不出声。

**做法**：用 Python 重写 `voice_daemon.py`：stdin 收文件路径 → Fish 合成 → 缓存（md5）→ 解码成 wav → `winsound` 播放 → 写 `speech.jsonl`。

**遇到的 Bug**

| 现象 | 原因 | 修法 |
|---|---|---|
| 开机就出声，盖住动画 | 新守护没识别 `prewarm` 标记 | 加 `if prewarm: 只合成不播放` |
| 只有问候没有 BGM | `bgm.ps1` 的参数名 `-File` 与 PowerShell 自带参数撞名 | 改名 `-Clip`；播放器换成 WPF MediaPlayer（能读 mp4 音轨） |
| 音量算成 0 | `[math]::Min(1, 0.2)` 被截成整数 | 强制 `[double]` |

## 迭代 4：语音延迟优化（提示词瘦身 + 缓存）

**原始需求**

> 「时间块设置成只有我问到和时间相关的话题时，她才去看一眼时间……顺序是：人设 → 关系 → 事实 → 记忆 → 时间 → 提示。」

**测量**：7B 提示词处理约 37–40 token/s；原 system 2374 字（≈950 token），首块 16.8 秒。

**改动**

1. 记忆检索附带的 213 字「输出格式」块，在鲸娘人格下不再注入（人设里已有）。
2. 事实块只取最近 3 条、每条 40 字，并过滤问句。
3. 防复读提示从 3 句×30 字缩到 2 句×24 字。
4. 手表块按需注入：只有命中时间/身体状态词才带。
5. 顺序调整为「人设 → 关系 → 事实 → 歌曲 → 记忆 → 时间 → 其余提示」，让不变的部分吃满 KV 缓存。

**结果**：提示词 2374 → 1891 字，首块 16.8s → **6.8s**。

## 迭代 5：流式识别 + 气泡草稿

**原始需求**

> 「我们说的时候，对话框先弹出来，我们一边说，对话框里就一边把我们说的话转成文字，直到我们说完后再把这段文字发给模型。」

**做法**

1. 装 `sherpa-onnx`，下载中文流式 paraformer（encoder 636MB + decoder 228MB）。
2. voice-chat 把音频块同时喂给流式识别，每 0.15 秒把草稿 POST 到 `/dsh-pet-7340/voice-draft`。
3. 宿主收到草稿：`petVoicePending.set(id, {silent:true})` + `state.writePet(id, "say", {text})` → **直接复用她会说话的那个气泡**，不用改客户端 UI。

**遇到的 Bug**

| 现象 | 原因 | 修法 |
|---|---|---|
| 气泡不出现 | 路由返回对象少了 `kind:"json"`，被当成文件下载 → 500 | 四处路由补 `kind`（顺带修好 `greet-now` 一直 500 的问题） |
| 唤醒突然失灵 | 流式解码卡死主录音线程 | 流式识别挪到独立线程，主线程只入队 |
| 同一句话两个音色 | `speakPetLine` 在模块作用域，调用不到闭包里的 `petPersonaState()`，异常被吞 → 回退默认音色 | 增加模块级镜像变量 `petWhoCache / petPersonaVoiceCache`，三个时机同步 |

## 迭代 6：声纹过滤（只认主人的声音）

**原始需求**

> 「我这里人有点多，别人说话的声音有点吵，我想让她通过声纹听出我的声音，别人的声音直接不理会。」

**做法**

1. 下载 CAM++ 中文声纹模型（28MB），用 sherpa-onnx 提取 192 维向量。
2. `voice-enroll.py` 录 4 段 × 4 秒，求平均向量存 `voice-print.json`。
3. `voice-chat.py` 每句识别前先算相似度，低于阈值直接忽略（连唤醒都不理）；档案改动自动热加载。

**实测分离度**：主人自己多段 0.69–0.82；vs 合成音 0.002–0.126；阈值取 0.45。

## 附：一次事故与恢复（也可作为"引导 AI 修 Bug"的素材）

搬迁数据目录时，AI 先移动了带 junction 的目录，导致递归复制、`daemon.ps1` 丢失。
后续通过：`_recover.ps1`（浅层文件）→ `_recover2.ps1`（.NET 长路径目录复制）→ 删除递归树 → 重建 junction 恢复。
教训写进了 `troubleshooting.md`：**移动目录前先删 junction，搬完立即验证关键文件**。
